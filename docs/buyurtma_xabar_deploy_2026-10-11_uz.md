## Deploy тартиби

Белгиланг: `[ ]` → `[x]` + сана.

- [ ] **1. Индекс** `admin_news (category ASC, createdAt DESC)` — жонлида йўқ
  (2026-10-11 текширилди).
  - `--force`сиз; чиқишдаги «Deleting N» қаторини ўқинг (production'да
    файлда йўқ қўлда яратилган индекслар бор).
  - Индекс `READY` бўлмагунча 2-қадам чиқмасин — акс ҳолда админ рўйхати
    `failed-precondition` хатосини беради.
  - Rollback: керак эмас (ишлатилмаган индекс зарарсиз).
- [ ] **2. Hosting (админ)** — жонли SHA устига шу commit.
  - Deploy олдидан жонли hash'ни текширинг (hosting навбати бошқа
    сессиялар билан умумий; gitignored `config.dart` ва APK'лар).
  - Rollback: Firebase Console → Hosting → олдинги релиз «Rollback».
- [ ] **3. Functions — фақат номи билан** (тўлиқ `functions:default` ЭМАС):
  `onAdminNewsCreate`, `onOrderCreate`, `onOrderUpdate`,
  `courierSubmitPayment`, `courierFinalizeCollection`, `courierMarkArrived`,
  `courierMarkCollectionArrived`, `courierMarkCarpetArrived`,
  `courierMarkAgroPickupArrived`.
  - ⚠ Бу branch'да deploy қилинмаган бошқа commit'лар бор — deploy branch
    жонли SHA'дан қурилсин, шу commit устига қўйилсин.
  - `notifyUserInApp` чақирадиган бошқа функциялар қайта deploy бўлгунча
    улар аввалгидек 2 push юборади (ёмонлашув йўқ).
  - Ресторан функциялари (`orderId` ресторан хабарида) — D-REST-15 (deploy
    қилинмаган) билан бирга кетади, эга қарори.
  - Rollback: шу функцияларни жонли SHA'дан номи билан қайта deploy.
    Хавфсиз: эски `onAdminNewsCreate` `pushDirect`ни эътиборсиз қолдиради —
    ҳолат аввалгидек (2 push) бўлади, маълумот бузилмайди.
- [ ] **4. APK** — илова қисми (бош badge, `orderId`сиз хабар картаси,
  «Йўлда»/«Бекор» ёрлиқлари). Қуриш вақти — эга қарори.
