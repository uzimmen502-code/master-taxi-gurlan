## 2. Мақсад

1. Ижарачи бир марта «шундай уй чиқса, хабар бер» дейди — мос эълон
   чиққанда push олади, иловани очиб ўтириши шарт эмас.
2. Эга эълон берганда «ҳудудингизда N киши шундай уй қидиряпти» деган
   сигнал олади (контактсиз).
3. Пуллик модель бузилмайди: push ва рўйхатда телефон, аниқ нуқта,
   кўча/уй рақами чиқмайди — улар аввалгидек пакет орқали очилади.

### Б-1. «Менга хабар бер» — сақланган қидирув (асосий қисм)

**Ижарачи томони (илова):** «Кўчмас мулк» экранида «🔔 Шундай уй
чиқса, хабар бер» тугмаси. Шакл: битим тури (ижара/сотув) · харитадан
марказ ёки «менинг жойим» · радиус (1 / 3 / 5 / 10 км) · хона
(мин–макс) · нарх (макс, ихтиёрий). Сақлангач, **ҳозир мос келадиган
эълонлар рўйхати дарҳол** кўрсатилади (push эмас).

**Маълумот (янги collection):**

```
realty_alerts/{alertId}            ← фақат сервер ёзади (callable)
  ownerId, deal, center{lat,lng}, geohash5, radiusKm,
  roomsMin, roomsMax, priceMax (int, UZS), pricePeriod,
  status: active | paused | expired, expiresAt (30 кун, узайтирса бўлади),
  createdAt, updatedAt
realty_alert_hits/{alertId}_{listingId}   ← детерминистик ID = idempotency
  alertId, listingId, ownerId, at, pushed: bool
```

- Callable'лар: `createRealtyAlert`, `updateRealtyAlert` (пауза/ўчириш),
  `listMyRealtyAlerts`. Лимит: 1 одамга **3 та актив** хабарнома
  (PROPOSED рақам). Сервер ҳамма майдонни текширади (18-қоида).
- Qoida: ўқиш — фақат эгаси ва админ; клиент ёзмайди (20-қоида).

**Сервер мослаштириш (trigger):**

1. `realty_listings/{id}` ёзилганда — **status `active`га ЎТГАНДА**
   (авто-тасдиқ, админ тасдиғи, таҳрирдан кейинги қайта тасдиқ —
   учаласи ҳам битта trigger'да) `matchRealtyAlerts(listingId)`.
2. `private/detail`дан аниқ нуқта олинади → радиусга мос geohash
   префикслари + 8 қўшни (`functions_demand/geo/geo.js` →
   `neighborPrefixes`, `precisionForRadiusKm` — мавжуд, қайта
   ёзилмайди) → `realty_alerts` сўрови (`status=active`, `deal`,
   `geohash5` диапазони).
3. Хотирада: аниқ масофа (`haversineKm`) ≤ радиус, хона, нарх, муддат;
   **эгасининг ўз хабарномаси чиқарилади**.
4. Ҳар мос келган учун `realty_alert_hits/{alertId}_{listingId}`
   **create** (бор бўлса — ўтказиб юборилади): trigger қайта ишласа ҳам
   push иккинчи марта кетмайди (21-қоида).
5. Push чегараси: 1 одамга кунига **10 та**, 23:00–07:00 тинч соат
   (ядродаги `alert` режими қоидаси билан бир хил — `functions_demand/
   core/config.js:122`, `notify/policy.js`; рақамлар қайта ёзилмайди,
   ўша конфигдан олинади — 7-қоида). Ошиб кетганлари фақат рўйхатда.

**Push ва inbox (махфийлик):**

- Матн: «Сиз қидираётган ҳудудда янги ижара: 2 хона, ~3 000 000 сўм/ой».
  **Телефон, кўча, уй рақами, аниқ нуқта — ЙЎҚ.**
- Inbox — `users/{uid}/realty_matches` (фақат эгаси ўқийди).
  ⚠️ `admin_news` **ИШЛАТИЛМАЙДИ**: у ҳаммага очиқ (`firestore.rules:1605`
  `allow read: if true`) — CONFIRMED; ундан ташқари `notifyUserInApp`
  + `onAdminNewsCreate` иккита push юбориши мумкин — INFERRED.
- Push тури `realty_match` → эълон тафсилоти экранига (ҳозир realty учун
  push маршрути бу branch'да йўқ — CONFIRMED, `push_navigation.dart`).

### Б-2. Эга талабни кўради (контактсиз)

## 4. Архитектура танлови — trade-off (эга қарори керак)

| | **A. `realty.js` ичида (тавсия)** | **B. Талаб-таклиф ядросида `realty` адаптери** |
|---|---|---|
| Йўналиш | Таклиф пайдо бўлганда ижарачига хабар — шу масала учун | Ядро ҳозир фақат «талаб → провайдер» томонга ишлайди; тескари йўналиш йўқ (CONFIRMED) |
| Муддат | Хабарнома 30 кун, узайтирилади | Талаб TTL ≤ 14 кун (`demand_input.schema.json:67-72`) |
| Inbox | Ижарачи томони (`users/{uid}/realty_matches`) | `demand_matches` провайдер калитида — ижарачи inbox'и йўқ |
| Push | Ядро қоидалари (лимит, тинч соат) **қайта ишлатилади** | Ядро push'и `demand_match` тури — нотўғри экранга олиб боради; digest юборувчи ҳали ёзилмаган |
| Таъсир доираси | Фақат realty, ядро тегилмайди | Деплой қилинган ядрони кенгайтириш — хавфлироқ |
| Камчилик | Иккинчи «мослаштириш» жойи пайдо бўлади | Кўпроқ иш, лекин ягона жой |

**Тавсия: A**, маълумот шакли B'га кейин кўчириладиган қилиб
(`geohash`, `radiusKm`, `priceMax` — ядро майдонлари билан бир хил ном).
Гео-ёрдамчи ва push қоидалари **ядродан олинади** — дубликат ёзилмайди
(4-, 7-, 43-қоидалар).

## 5. Нархи (Firestore, 37-қоида) — тахминий

- Янги эълон тасдиқланганда: ~9 та префикс сўрови (одатда ҳар бирида
  0–10 хабарнома) + мос келганлар учун 1 create + 1 push. 1 000 та актив
  хабарнома бўлса ҳам эълонга ~10–50 read.
- Хабарнома яратиш: 1 write + бир марталик «ҳозир мос келганлар»
  сўрови (≤ 50 read).
- Listener йўқ: inbox очилганда бир марта ўқилади.

## 6. Тестлар (32-, 34-қоидалар)

- Позитив: радиус ичидаги ижара → 1 hit + 1 push.
- Негатив: бошқа битим тури, радиусдан ташқари, хона/нарх мос эмас,
  эгасининг ўз хабарномаси, `paused`/`expired` → push йўқ.
- Чегара: радиус чегарасидаги нуқта; `priceAmount` йўқ эски эълон.
- Idempotency: trigger 2 марта → push 1 та (emulator'да, ҳақиқий tx).
- Махфийлик: push матни ва inbox ёзувида телефон/кўча/нуқта йўқ.
- Qoida тестлари: `realty_alerts`, `realty_alert_hits`,
  `users/{uid}/realty_matches` — бегона ўқий олмайди, клиент ёза олмайди.

## 7. Чиқариш (42-қоида)

`OFF → INTERNAL` (фақат админ рақамлари) `→ PILOT` (бир туман)
`→ PUBLIC`. Ҳар босқичда push сони ва шикоятлар кузатилади.
