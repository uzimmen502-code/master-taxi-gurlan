# TV Market (video commerce)

Home attraction + full-screen vertical feed + seller mini-shop / AVA vitrine. Module id `tv_market` in `kKnownModuleIds`. Storage: `tv_clips/{ownerPhone}/{file}`, shop photos `tv_shop/{ownerPhone}/{file}`. Settings: `settings/app.tvAutoApprove` (true → create `active`, false → `pending`).

## Domain (do not rebuild collections)
Five layers, flat Firestore + IDs — not nested subcollections (feed needs top-level `tv_clips`):
- `users/{uid}` 🔒 private account (wallet, address, role)
- `tv_public_profiles/{uid}` 👤 public face (name; photo later). App-wide display, not `users` reads
- `tv_shops/{uid}` 🏪 one shop per user
- `tv_shop_items/{id}` 🛍️ Offer (commerce source of truth: title/optional price/`photoUrl`+`photoUrls` 1–5/kind). Domain name Offer; keep collection id
- `tv_clips/{id}` 🎥 video; `shopItemId` optional (clip-only posts allowed). Feed denorms title/price/ownerName/district
Do not rename to generic `shops`/`offers`/`clips` (collides with platform_store / ads). Owner edit/delete on overlay, home card, own clip grid; edit syncs offer if `shopItemId` set; delete unlinks `clipIds`.

## AVAGram (3-tab unified feed) — one interface, source/ranking differs per tab
Decision: single video interface (Like/Comment/Share/Save/Profile/Shop unchanged) across 3 tabs in `tv_market_feed_screen.dart` (`TabController` len 3, `bottom: TabBar`); only the Firestore query source differs. **Not** separate collections — `tv_clips.category` extended `product|service` → `+news|+ad`, so every existing feature (like/comment/save/follow/avatar) works on new/ad content automatically (do not build parallel collections/repos for these).
- Tab 0 AVAGram: `categories: null` → unchanged existing query (all categories, incl. news/ad)
- Tab 1 Кун янгиликлари: `categories: ['news']`
- Tab 2 Реклама ва Эълонлар: `categories: ['product','service','ad']`
- `TvClipsRepository._withCategory()` adds `.where('category', whereIn: categories)` to `fetchNearby`/`fetchAllActive`/`fetchHomePage` (all now take optional `categories` param). Indexes added: `(status,districtId,category,createdAt desc)`, `(status,category,createdAt desc)` in `firestore.indexes.json`.
- **News** (`category:'news'`): user does NOT pick this — auto-detected at publish time only for non-shop clips via `tv_news_detector.dart` `tvLooksLikeNews(title, description)` (keyword match, 3-script list, no ML). Sets `expiresAt = now+48h`. TTL: `expireTvContent` sched CF (functions/index.js, every 15 min) flips `status:'active'→'expired'` when `createdAt < now-48h` AND deletes Storage video/poster/`tv_clip_variants/{id}/` (user's explicit choice — profile/like stats survive separately, only clip content is removed). Feed already filters `status=='active'` so expired clips vanish with no rules change.
- **Ad** (`category:'ad'`): explicit 3rd segment in `tv_publish_screen.dart`'s category `SegmentedButton` (hidden in edit mode — ads not editable via this screen yet). **Tariff table** (product-specified, see AVA TV rate card): 5 tiers `tvAdTiers` = `basic|visibility|home|premium|pro_max` (Оддий видео/Кўпроқ кўриниш/Home/Premium/Pro Max — each implies different placement/visibility priority, but the *ranking/placement algorithm itself is not built yet*, only pricing + tier selection + storage on the clip via `adTier`) × 3 durations `tvAdDurationOptions` = `7|15|30` days (**1-day option removed** per product decision). Price = `settings/app.tvAdPricing.{tier}.{durationDays}` (admin-editable, see below) else `tvAdTierPricingDefault`/`TV_AD_TIER_PRICING_DEFAULT` fallback — both mirrored client (`tv_ad_service.dart`) + server (`functions/index.js`), values match the rate card image the product owner supplied (basic 20k/30k/50k … pro_max 100k/150k/250k so'm). Payment: client **cannot** write `bonusBalance` directly (`walletFieldsUntouched` rule) so `category:'ad'` docs are created *only* by callable `publishTvAd` (Admin SDK, atomic wallet debit + `{uid}/wallet_ledger` entry `type:'tv_ad_purchase'` + clip create in one transaction, `tier` param validated against `TV_AD_TIERS`) — rules explicitly block client `create`/`update` into `category:'ad'` and block client edits of `expiresAt`/`adDurationDays`/`adTier` on any clip (see `match /tv_clips/{clipId}` create/update conditions). TTL: same `expireTvContent` sweep, `expiresAt < now` → `status:'expired'` (files **kept**, unlike news — possible renewal later, not yet built).
- **Admin pricing UI**: `lib/features/admin_web/screens/tv_ad_pricing_admin_screen.dart` — 5×3 number-field grid, direct Firestore write to `settings/app.tvAdPricing` (rule `match /settings/{docId} { allow create,update: if isAdmin() && docId != 'tv_social' }` — no CF needed, same pattern as `tvAutoApprove` toggle in `tv_clips_moderation_screen.dart`). Wired into `admin_shell.dart` sidebar as section `'AVAGram реклама нархи'`.
- **Tier placement/ranking** (`tv_clip_shuffle.dart`): `TvClip.adBoostWeight` (basic=0,visibility=1,home=2,premium=3,pro_max=4) + `TvClip.showsOnHome` (`!isAd || tier in {home,premium,pro_max}`). `tvApplyAdTierPriority(items, {maxBoostedSlots=6})` runs right after `tvShuffleClips` in `fetchNearby`/`fetchAllActive`/`fetchHomePage` — promotes up to 6 highest-weight ads to the front (stable among ties), rest of the list (incl. overflow boosted ads beyond the cap) keeps its shuffle order untouched — deliberately NOT a full recsys score, just a bounded front-slot promotion so a flood of paid ads can't wall off the whole feed. `fetchHomePage`'s per-doc loop now checks `c.showsOnHome` before adding (basic/visibility ads silently skipped, `seen` still marked so pagination doesn't re-fetch them) — `fetchNearby`/`fetchAllActive` (AVAGram/Реклама tabs) show every tier, no eligibility filter, only the priority boost. "Видео лента" vs "Оддий лента" (basic vs visibility placement text in the rate card) map to the same single feed in this app — only the boost weight differs, there's no separate video-only feed surface.
